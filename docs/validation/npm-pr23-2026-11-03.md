## npmとBiome

`npm ci`は38パッケージをインストールし、exit 0。
38個のインストール済みバージョンがlockと一致し、macOS/ARM64に適用される
24個のNode engine条件をv24.22.0が満たすことを確認した。
mainと比較してBiomeの`>=14.21.3`、Wrangler/Miniflareの`>=22.0.0`、
sharpの`>=20.9.0`、undiciの`>=20.18.1`は変わっていない。
非対応プラットフォームのoptional binaryが未インストールなのは正常。
Windows/ia32専用sharpの`^20.9.0`は、このMacのengine判定対象ではない。

`biome --version`は2.6.3。
`biome check --verbose package.json package-lock.json biome.json`はexit 0で、
実際に処理したのは`package.json`と`biome.json`の2ファイルだった。
`package-lock.json`はBiomeのprotected fileで、検査済みとは扱わない。
lockのJSON読取りと`npm ci`で構文・manifestとの整合性を確認した。

schema 2.5.8とCLI 2.6.3の差は情報診断で、設定読込みや検査を失敗させない。
mainの正確なnpm manifest/lock/configを一時ディレクトリへ展開して
`npm ci`と`biome check --vcs-enabled=false --verbose package.json package-lock.json biome.json`
を実行すると、旧CLI 2.5.15でも同じ種類の情報診断とexit 0を再現した。
`biome migrate`の非書込みpreviewもschema URLの1行だけを提案した。
PR23で新たに生じた設定不良は確認できなかったため、schemaや研究JSONを変更していない。
リポジトリ全体のBiome lint/formatや自動修正は実行していない。

npm 11.19.1はesbuild/fsevents/workerdの未承認install scriptを警告した。
mainのbaselineでも同じ警告が出た。承認設定を変更せず、後述の
CLI/native runtime動作を確認した。任意のfile watcherの動作は未検証。

## Wranglerとオフライン代替検証

Cloudflare資格情報の環境変数を外し、`CI=1 WRANGLER_SEND_METRICS=false`で
`wrangler --version`、`wrangler pages deploy --help`、
`wrangler pages functions build --help`を実行し、すべてexit 0。
Wranglerは4.152.0。Pages deployには`--dry-run`がないためdeployを実行していない。
このリポジトリはPythonによる静的site buildなので、Functionsを新設していない。

`scripts.build_agency_site.build_site`に空の合成JSONと空の画像ディレクトリを渡し、
一時ディレクトリに`index.html`、`data.json`、`_headers`が生成されること、
agency配列とassetsが空であることをassertした。実際の研究データを使ったsite buildではない。

Biome、workerd、esbuildの選択されたbinaryはMach-O ARM64。
`workerd --version`は2026-10-19、`esbuild --version`は0.28.2。
Miniflare 5.20261019.2-betaのexport済み`convertV4MiniflareOptions`で
合成Workerを構成し、telemetryを無効化、hostを127.0.0.1に限定した。
`dispatchFetch`のHTTP 200と固定文字列の完全一致をassertし、
`finally`で`dispose`してruntimeを停止した。
旧形式のconstructor引数が失敗することはmainのMiniflareでも再現し、
このPRの回帰とは扱っていない。
